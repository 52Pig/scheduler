# 安全模型与权限

## 资产和信任边界

- 任务定义、命令参数、依赖图、运行历史及输出。
- 服务账户可访问的文件、目录、网络资源和外部系统。
- 本机 `127.0.0.1:1000` 上的控制台和 HTTP API。
- Windows 服务配置、部署目录、SQLite 状态库及健康监控计划任务。

任务注册和手动运行是高权限动作：命令以 SchedulerService 的 LocalService 身份执行。当前 API 没有认证/授权/审计，也没有跨任务身份隔离，因此本机其他进程也可能访问写 API。绑定 loopback 限制远程网络访问，但不是本机身份认证。

## 当前控制措施

- 默认只监听 `127.0.0.1`；远程接入需经过配置了身份认证和 TLS 的可信代理。
- 命令由参数数组启动，`shell=False`；避免框架层 shell 字符串拼接，但不降低“可信用户可执行命令”的风险。
- Windows 服务使用 LocalService；任务进程继承相同身份和权限。
- 安装器为调度器自己的文件和状态目录设置权限，不应为具体业务任务修改权限。
- 任务日志限制长度并保留五天，但当前不做敏感字段识别或脱敏。

## 操作者要求

- 只允许可信本机账户或经过身份认证的受控入口访问注册、修改、删除和运行 API。
- 不要将服务端口直接暴露给局域网或互联网。反向代理必须验证身份、限制写操作、使用 TLS 并记录操作者审计信息。
- 任务所有者授予服务身份读取其解释器/脚本、读写业务目录和访问网络资源的最小权限；禁止对整个用户目录或工作站凭据库授予宽泛权限。
- 命令参数、脚本路径、工作目录和日志都可能泄露业务信息。不要把密码、token 或私钥写入任务定义和命令行参数；当前系统没有 secret store。
- 服务身份变更、代理暴露或危险任务注册需要安全评审和恢复方案。

## 威胁与缓解

| 威胁 | 影响 | 当前缓解/残余风险 |
| --- | --- | --- |
| 未授权注册命令 | 以服务身份执行任意代码 | 默认 loopback；API 无身份认证。远程访问必须在认证代理后 |
| 恶意/失控任务 | 删除可访问文件、消耗资源、访问网络 | LocalService 和任务 ACL 最小化；没有 CPU/内存/进程数配额或沙箱 |
| 命令参数含密钥 | 进程列表、任务定义或日志泄漏凭据 | 将凭据放入任务自行保护的凭据提供机制；框架当前不能安全注入密钥 |
| 输出含敏感数据 | 本机运行记录泄漏 | 控制日志内容；输出限长和五天保留不等于脱敏/访问控制 |
| 服务重启/超时中断 | 外部操作部分完成后状态不确定 | 任务实现幂等和业务去重；运维先核验副作用再重跑 |
| SQLite 文件被损坏或误删 | 任务定义和运行历史丢失 | 建立离机备份、限制状态目录写权限并定期演练恢复 |

## 不具备的能力

没有任务级 OS 身份、容器沙箱、网络策略、秘密信息托管、静态命令白名单、用户/角色模型、变更审计或远程 worker 隔离。不要把部署文档或代理配置误认为这些产品能力已经存在。遇到多租户或不可信提交者时，应先实现身份授权和任务隔离，再开放注册能力。
