# ADR 0001: 单机单实例调度

- 状态：Accepted
- 日期：2026-11-19
- 范围：调度器运行拓扑和持久化

## 背景

当前目标是在一台受控 Windows 工作站上提供常驻服务、网页管理、CLI/API 注册和依赖工作流。此部署规模暂不需要远程 worker 或多副本故障转移。

## 决定

以一个常驻 Windows Service 运行 FastAPI、APScheduler、工作流编排和本机进程执行。SQLite 保存任务定义、触发器和运行历史。WinSW 管理进程，SYSTEM 计划任务在健康检查连续失败时尝试恢复服务。

## 后果

- 部署简单，触发器和运行历史可在进程重启后恢复。
- 控制面和任务执行故障域相同；服务重启会中断执行。
- SQLite 不提供多调度器实例的 leader election 或执行租约；同一生产数据库不得由多个调度服务并发调度。
- 需要多机、高可用或更大吞吐时，必须引入并发安全的数据库、单一调度所有权和独立 worker，并进行迁移设计。

## 考虑过的方案

- 立即采用分布式队列和容器集群：当前维护成本和需求不匹配，且不能自动解决任务幂等和权限问题。
- 仅使用 Windows Task Scheduler：难以满足依赖图、运行状态、日志查询和统一 Web 管理需求。
