# ADR 0005: 按运行 ID 停止单次任务

- 状态：Accepted
- 日期：2026-11-19
- 范围：运行控制 API 和本地执行器

## 背景

任务可能长时间运行或需要人工干预。仅有运行按钮会迫使操作者停止整个调度服务，影响其他工作流，并让运行记录无法准确描述人工终止。

## 决定

停止操作以单次 run ID 为目标，通过 `POST /api/runs/{run_id}/stop` 发起。当前服务进程维护活动 run 到本地执行控制句柄的映射。Windows 使用 `taskkill /T /F` 尝试终止该运行的进程树；POSIX 使用独立进程组并发送终止信号。记录以 `cancelled` 作为终态，输出追加操作说明。已结束或不存在的运行不接受停止请求。

## 后果

- 操作者无需停止整个调度服务；停止一个节点不会取消工作流中的兄弟节点或其他运行。
- 停止仅作用于当前服务进程能控制的本机进程；脱离进程树的守护进程、远程作业和已完成的外部副作用不保证被取消/回滚。
- 服务重启后活动进程控制句柄不再存在；运行记录按中断恢复规则标成失败且结果未知，不能声称已取消。
- 若未来增加远程 worker，取消请求必须带执行尝试 ID、worker 所有权和确认状态，并处理租约失效后的迟到响应。

## 考虑过的方案

- 停止某个 job ID 下全部执行：会误停同一任务的并行/重复运行。
- 停止整个 workflow run：操作者可能只想中止一个阻塞节点，其他独立分支应继续。
- 仅在 UI 隐藏/标记停止：不能终止 OS 进程，也会产生不真实的运行状态。
