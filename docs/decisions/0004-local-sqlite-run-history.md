# ADR 0004: SQLite 运行状态与短期输出保留

- 状态：Accepted
- 日期：2026-11-19
- 范围：定义、运行状态和日志存储

## 背景

单机部署需要在进程重启后保留任务定义、APScheduler 触发器和近期执行结果，同时避免额外数据库服务的运维成本。

## 决定

SQLite 是当前持久化存储。任务定义更新保留递增版本，运行记录记录定义版本、workflow run ID、状态、退出码和合并后的输出。输出最多保留尾部 20 KB；已结束运行记录保留五天，运行中记录不清理。

## 后果

- 本地安装和备份路径简单，适合低并发单机部署。
- SQLite 写入争用、单文件故障域、无集中日志和短期留存限制了吞吐与审计能力。
- 当前 schema 通过启动时增量兼容逻辑调整，没有完整版本化迁移系统；升级需备份并测试。
- 多实例、长期日志或审计要求出现时，应分别迁移到协调型数据库和有访问控制的日志/事件存储。

## 考虑过的方案

- 生产期把全部子进程输出保存在数据库：会造成数据库无界增长。
- 只保留内存状态：进程重启后会丢失定义和运行历史。
