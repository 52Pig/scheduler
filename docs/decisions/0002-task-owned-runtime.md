# ADR 0002: 任务所有者提供运行时，框架执行参数数组

- 状态：Accepted
- 日期：2026-11-19
- 范围：任务定义和执行器

## 背景

任务可能使用不同 Python 环境、PowerShell、Bash、Node.js 或原生程序。框架若负责安装和维护每个任务环境，会造成隐式依赖、升级耦合和难以审计的副作用。

## 决定

任务定义保存 executable 与 argv 数组。执行器将该数组直接交给 `subprocess`，使用 `shell=False`。任务所有者维护解释器路径、脚本、库、数据、访问权限和安全重跑语义。框架只管理调度、依赖、启动、退出码、超时和运行日志。

## 后果

- 多运行时接入不要求框架内置各语言解析器。
- 任务环境故障由任务所有者负责，服务身份必须拥有必要的最小权限。
- Shell 表达式不由框架解析；任务应将 shell 脚本作为文件并明确注册 shell executable。
- 若增加容器或远程 backend，应将其作为显式执行器实现和版本化任务规格，不能通过悄悄修改全局运行时改变任务行为。

## 考虑过的方案

- 框架为每个任务创建/更新虚拟环境：职责越界，且不能覆盖 Bash、系统工具等运行时。
- 一个 shell 字符串字段：引入转义和命令注入风险，且不同操作系统语义不一致。
