# 测试与发布

## 测试分层

| 范围 | 主要覆盖 | 对应测试 |
| --- | --- | --- |
| 数据与调度服务 | 触发器恢复、依赖 DAG、并行分支、失败跳过、执行退出码和增量输出 | `tests/test_scheduler.py` |
| HTTP/API | 请求校验、任务 CRUD、手动 scope、运行中详情、日志过滤和保留期 | `tests/test_api.py` |
| CLI | 参数和 HTTP 请求映射、服务不可达与错误处理 | `tests/test_cli.py` |
| Windows 部署 | SQLite 一致性迁移、不覆盖目标数据库、服务恢复脚本契约 | `tests/test_deploy.py` |
| Web 静态代码 | JavaScript 语法；人工/浏览器验证交互、状态、窄屏和可访问性 | `scheduler/static/` |

## 本地质量门禁

在项目环境安装开发依赖后执行：

```powershell
python -m pip install -e ".[dev]"
python -m pytest -q
python -m ruff check .
python -m ruff format --check .
node --check scheduler/static/app.js
node --check scheduler/static/logs.js
```

修改 PowerShell 脚本时至少用 PowerShell Parser 做语法解析；变更 Windows 服务行为时还要在隔离/维护窗口执行对应部署验证。单元测试不应依赖在线服务、真实行情任务、真实数据目录或开发者桌面环境。

## 必须覆盖的行为

- 任务定义：合法/非法输入、唯一 ID、编辑版本变化、依赖缺失/环/跨根汇合。
- DAG 执行：父节点成功后执行、失败/超时向后传播、独立分支继续、manual self/downstream 范围。
- 外部进程：精确参数传递、退出码、异常 executable、工作目录、超时、实时 stdout/stderr、输出上限、运行中查询、停止请求及进程树终止。
- 持久化：启动恢复、旧 schema 兼容、五天保留、运行中记录不被清理、备份完整性。
- API/UI：运行中可见、刷新行为、空/失败状态、日志分页和链接、安全转义、窄屏与键盘操作。
- 部署：服务启动/停止、健康监控恢复、数据库迁移不覆盖既有数据、服务身份权限。

测试外部可观察行为。对时间行为使用固定时间/可控触发器；对进程行为使用短时临时命令。超时和破坏性恢复只在隔离临时目录执行。

## 发布门禁

当前仓库没有声明 CI 发布流水线；以下门禁由变更负责人执行并在评审中附结果。

1. 确认变更范围、兼容性、依赖和数据库迁移计划；架构边界变化增加 ADR。
2. 执行上述测试和静态检查；检查完整差异及文档链接/命令。
3. 由非作者评审。涉及命令执行、权限、网络暴露、数据迁移或服务身份的改动需相关代码所有者重点评审。
4. 发布前备份生产 SQLite 数据库，确认没有运行中的关键任务并安排维护窗口。
5. 部署调度器自身程序和依赖；不得安装/升级某个已注册任务的解释器或依赖。
6. 验证服务状态、健康接口、端口、任务定义、下一次计划、运行日志和健康监控任务。
7. 对执行框架改动运行无副作用的短任务冒烟测试，验证运行状态、实时输出、完成状态，再移除临时任务。
8. 记录版本、数据库备份、部署时间、验证结果和回滚决定。

## 回滚

回滚前判断新版本是否已经修改数据库 schema。仅当旧代码与新 schema 兼容时，才可直接恢复旧程序。若 schema 变更不可逆，应通过经过验证的数据库副本恢复；恢复会丢失备份时间之后的新任务定义和运行历史，需提前评估并记录。回滚后检查服务健康和计划触发器，再恢复业务运行。
